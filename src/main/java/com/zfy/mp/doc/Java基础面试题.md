## 1. Java 有哪些语言特点？

Java 的主要特点有：

- 面向对象：支持封装、继承、多态
- 跨平台：一次编译，到处运行，依赖 JVM 屏蔽操作系统差异
- 自动内存管理：对象由 JVM 管理，通过 GC 回收
- 强类型语言：变量类型明确，编译期会做类型检查
- 生态成熟：Spring、MyBatis、Netty、Dubbo 等生态丰富

面试回答：

Java 是一门面向对象的强类型语言，最大的特点是跨平台。Java 源码会先编译成字节码，然后由不同平台上的 JVM 执行，所以可以做到一次编译，到处运行。另外 Java 提供了自动内存管理和垃圾回收机制，降低了手动管理内存的复杂度。

## 2. Java 为什么能跨平台？

Java 跨平台依赖 JVM。

执行流程：

```text
Java 源码
  -> javac 编译成 .class 字节码
  -> JVM 加载字节码
  -> JVM 解释执行或 JIT 编译执行
```

面试回答：

Java 程序不是直接编译成某个操作系统的机器码，而是先编译成平台无关的字节码。不同操作系统安装对应的 JVM，由 JVM 把字节码解释或编译成本地机器指令执行，所以 Java 程序本身可以跨平台，真正和平台相关的是 JVM。

## 3. JDK、JRE、JVM 有什么区别？

区别：

- JVM：Java 虚拟机，负责运行字节码
- JRE：Java 运行环境，包含 JVM 和运行 Java 程序需要的核心类库
- JDK：Java 开发工具包，包含 JRE、编译器、调试工具等

面试回答：

JVM 是运行 Java 字节码的虚拟机；JRE 是 Java 运行环境，包含 JVM 和核心类库；JDK 是开发工具包，除了 JRE，还包含 javac、javadoc、jdb 等开发工具。开发 Java 程序需要安装 JDK，只运行 Java 程序通常 JRE 就够了。

## 4. Java 程序从编写到运行经历了哪些步骤？

流程：

```text
编写 .java 文件
  -> javac 编译成 .class 字节码
  -> 类加载器加载 class
  -> JVM 执行字节码
  -> 热点代码可能被 JIT 编译成本地机器码
```

面试回答：

Java 程序首先由 javac 编译器把 `.java` 文件编译成 `.class` 字节码文件，然后 JVM 通过类加载器加载字节码，经过验证、准备、解析、初始化等步骤后执行。执行过程中，JVM 可以解释执行字节码，也可以把热点代码通过 JIT 编译成本地机器码来提升性能。

## 5. Java 中有哪些基本数据类型？

Java 有 8 种基本数据类型：

```text
byte、short、int、long
float、double
char
boolean
```

面试回答：

Java 的基本数据类型一共有 8 种，分为整数类型、浮点类型、字符类型和布尔类型。整数类型包括 byte、short、int、long；浮点类型包括 float、double；字符类型是 char；布尔类型是 boolean。

## 6. 基本类型和包装类型有什么区别？

区别：

- 基本类型存储的是值
- 包装类型是对象，存储的是对象引用
- 基本类型不能为 `null`
- 包装类型可以为 `null`
- 泛型中不能使用基本类型，只能使用包装类型

面试回答：

基本类型是 Java 语言内置的数据类型，存储的是具体值；包装类型是对应的对象类型，比如 int 对应 Integer。包装类型可以为 null，也可以用于泛型和反射等场景。基本类型性能通常更好，但在需要对象语义时要使用包装类型。

## 7. 自动装箱和自动拆箱是什么？

自动装箱：

```java
Integer num = 10;
```

本质类似：

```java
Integer num = Integer.valueOf(10);
```

自动拆箱：

```java
int value = num;
```

本质类似：

```java
int value = num.intValue();
```

面试回答：

自动装箱是基本类型自动转换成包装类型，自动拆箱是包装类型自动转换成基本类型。它是编译器帮我们做的语法糖。需要注意，如果包装类型为 null 时发生自动拆箱，会抛出 NullPointerException。

## 8. Integer 的缓存机制是什么？

示例：

```java
Integer a = 127;
Integer b = 127;
System.out.println(a == b); // true

Integer c = 128;
Integer d = 128;
System.out.println(c == d); // false
```

原因：

`Integer.valueOf` 默认会缓存 `-128` 到 `127` 范围内的对象。

面试回答：

Integer 在自动装箱时会调用 `Integer.valueOf`，该方法默认缓存了 `-128` 到 `127` 的 Integer 对象。所以这个范围内的值会复用同一个对象，使用 `==` 比较可能为 true；超过这个范围通常会创建新对象，`==` 比较为 false。实际开发中包装类型比较数值应该使用 `equals`。

## 9. `==` 和 `equals` 有什么区别？

`==`：

- 基本类型比较值
- 引用类型比较对象地址

`equals`：

- 默认和 `==` 一样比较地址
- 很多类会重写 `equals`，比如 String、Integer

面试回答：

`==` 如果比较基本类型，比的是值；如果比较引用类型，比的是对象地址。`equals` 是 Object 类的方法，默认也是比较地址，但很多类会重写它来比较对象内容，比如 String 比较的是字符串内容。

## 10. hashCode 和 equals 有什么关系？

约定：

- 如果两个对象 `equals` 为 true，那么它们的 `hashCode` 必须相同
- 如果两个对象 `hashCode` 相同，它们的 `equals` 不一定为 true
- 如果重写 `equals`，通常也要重写 `hashCode`

面试回答：

`equals` 用于判断两个对象是否相等，`hashCode` 用于计算对象的哈希值。Java 规定，如果两个对象通过 equals 判断相等，那么它们的 hashCode 必须相同。否则在基于哈希的数据结构中可能出现逻辑错误。所以重写 equals 时，通常必须同时重写 hashCode。

## 11. 为什么重写 equals 时必须重写 hashCode？

原因：

如果只重写 equals，不重写 hashCode，两个逻辑相等的对象可能有不同的 hashCode。

面试回答：

因为一些基于哈希的数据结构会先根据 hashCode 定位，再使用 equals 判断是否相等。如果两个对象 equals 为 true，但 hashCode 不同，就可能被放到不同位置，导致查找、去重等逻辑出错。所以只要重写 equals，就应该同步重写 hashCode，保证二者语义一致。

## 12. 面向对象三大特性是什么？

三大特性：

- 封装
- 继承
- 多态

面试回答：

封装是隐藏对象内部实现，只对外暴露必要接口；继承是子类复用父类的属性和方法，表达 is-a 关系；多态是父类引用指向子类对象，运行时根据实际对象类型执行对应方法。三者共同提高了代码的复用性、扩展性和维护性。

## 13. 什么是封装？

封装是把属性和行为包装到对象内部，对外隐藏实现细节。

常见方式：

- 属性使用 `private`
- 通过方法暴露访问入口
- 对入参做校验

面试回答：

封装就是把对象的状态和行为放到类内部，对外只提供必要的方法。这样可以隐藏实现细节，避免外部随意修改对象状态，提高代码安全性和可维护性。

## 14. 什么是继承？

继承是子类获得父类属性和方法的机制。

特点：

- Java 只支持单继承
- 子类可以重写父类方法
- 子类不能直接访问父类 private 成员

面试回答：

继承用于表达父子关系和实现代码复用。子类可以继承父类的非私有属性和方法，也可以重写父类方法来扩展行为。Java 只支持类的单继承，主要是为了避免多继承带来的复杂性。

## 15. 什么是多态？

多态是同一个父类引用，在运行时表现出不同子类行为。

示例：

```java
Animal animal = new Dog();
animal.say();
```

面试回答：

多态指父类引用可以指向子类对象，调用方法时会根据实际对象类型执行子类重写后的方法。它的前提是继承或接口实现、方法重写、父类引用指向子类对象。多态可以提高程序扩展性，减少对具体实现类的依赖。

## 16. 重载和重写有什么区别？

重载：

- 同一个类中
- 方法名相同
- 参数列表不同
- 和返回值无关

重写：

- 子类重写父类方法
- 方法名、参数列表通常相同
- 返回值类型要兼容
- 访问权限不能更严格

面试回答：

重载发生在同一个类中，方法名相同但参数列表不同，属于编译期多态。重写发生在父子类之间，子类对父类方法进行重新实现，属于运行期多态。

## 17. 接口和抽象类有什么区别？

区别：

- 抽象类可以有成员变量、普通方法、抽象方法
- 接口主要定义行为规范
- 一个类只能继承一个抽象类
- 一个类可以实现多个接口
- 抽象类表达 is-a，接口表达 can-do

面试回答：

抽象类更适合表达一类对象的公共父类，可以包含公共状态和公共实现；接口更适合定义能力或规范，一个类可以实现多个接口。选择时，如果多个类有共同属性和默认实现，可以用抽象类；如果只是定义行为约束，优先使用接口。

## 18. final 关键字有什么作用？

`final` 可以修饰：

- 类：不能被继承
- 方法：不能被重写
- 变量：只能赋值一次

面试回答：

final 表示不可改变。修饰类时，该类不能被继承；修饰方法时，该方法不能被子类重写；修饰变量时，变量只能赋值一次。需要注意，final 修饰引用类型时，不能改变引用地址，但对象内部内容仍然可能被修改。

## 19. static 关键字有什么作用？

`static` 表示属于类，而不是属于对象。

可以修饰：

- 静态变量
- 静态方法
- 静态代码块
- 静态内部类

面试回答：

static 修饰的成员属于类本身，随着类加载而初始化，不依赖具体对象。静态方法中不能直接访问非静态成员，因为非静态成员属于对象，必须先有对象实例。

## 20. this 和 super 有什么区别？

`this`：

- 表示当前对象
- 可以访问当前类属性和方法
- 可以调用当前类构造方法

`super`：

- 表示父类部分
- 可以访问父类属性和方法
- 可以调用父类构造方法

面试回答：

this 指向当前对象，常用于区分成员变量和局部变量，也可以调用当前类其他构造方法。super 用于访问父类成员或调用父类构造方法。构造方法中如果要调用 this 或 super，必须放在第一行，并且二者不能同时出现。

## 21. String 为什么不可变？

原因：

- String 类被 `final` 修饰，不能被继承
- 内部用于存储字符的数据结构不可随意修改
- String 没有提供修改自身内容的方法

好处：

- 线程安全
- 可以放入字符串常量池
- 可以缓存 hashCode
- 适合作为 key

面试回答：

String 是不可变对象，一旦创建后内容不能改变。这样做的好处是线程安全，可以安全地共享字符串对象；也能支持字符串常量池复用，减少内存开销；同时 String 常用于 key，不可变可以保证哈希值稳定。

## 22. String、StringBuilder、StringBuffer 有什么区别？

区别：

- String：不可变，每次修改都会产生新对象
- StringBuilder：可变，线程不安全，性能较好
- StringBuffer：可变，线程安全，方法加了 synchronized

面试回答：

String 适合少量字符串操作，因为它不可变，频繁拼接会产生较多临时对象。StringBuilder 适合单线程下大量字符串拼接，性能更好。StringBuffer 和 StringBuilder 类似，但它的方法是同步的，线程安全，性能相对低一些。

## 23. String str = "abc" 和 new String("abc") 有什么区别？

区别：

```java
String s1 = "abc";
String s2 = new String("abc");
```

- `"abc"` 会使用字符串常量池
- `new String("abc")` 会在堆中创建新对象

面试回答：

`String s1 = "abc"` 会优先从字符串常量池中查找，如果没有就创建一个常量池对象。`new String("abc")` 会在堆中创建一个新的 String 对象，同时字面量 `"abc"` 也会涉及常量池。所以二者用 `==` 比较通常是 false，用 `equals` 比较内容是 true。

## 24. 什么是字符串常量池？

字符串常量池是 JVM 为了复用字符串字面量而维护的一块区域。

面试回答：

字符串常量池用于保存字符串字面量，目的是减少相同字符串的重复创建。比如多个地方使用 `"abc"`，通常会复用常量池中的同一个对象。String 的不可变性是常量池能够安全复用的前提。

## 25. Object 类有哪些常用方法？

常用方法：

- `equals`
- `hashCode`
- `toString`
- `getClass`
- `clone`
- `wait`
- `notify`
- `notifyAll`

面试回答：

Object 是所有 Java 类的根类。常用方法有 equals、hashCode、toString、getClass、clone 等。equals 和 hashCode 常用于对象相等判断，toString 用于输出对象信息，getClass 用于获取运行时类型。

## 26. clone 方法了解吗？

`clone` 用于复制对象。

注意：

- 默认是浅拷贝
- 类需要实现 `Cloneable`
- 否则可能抛出 `CloneNotSupportedException`

面试回答：

clone 是 Object 提供的对象复制方法。默认 clone 是浅拷贝，也就是只复制对象本身，引用类型字段仍然指向原来的对象。如果需要完全复制内部引用对象，需要自己实现深拷贝。实际开发中 clone 使用不多，更多会通过构造方法、工厂方法或序列化等方式复制对象。

## 27. 深拷贝和浅拷贝有什么区别？

浅拷贝：

- 复制对象本身
- 引用类型字段仍然指向原对象中的引用

深拷贝：

- 复制对象本身
- 引用类型字段指向新的复制对象

面试回答：

浅拷贝只复制对象的基本字段和引用地址，所以两个对象内部的引用字段可能指向同一个对象。深拷贝会把引用字段指向的对象也复制一份，两个对象之间不会共享内部引用对象。

## 28. Java 异常体系是怎样的？

结构：

```text
Throwable
├── Error
└── Exception
    ├── RuntimeException
    └── Checked Exception
```

面试回答：

Java 异常体系的顶层是 Throwable，下面分为 Error 和 Exception。Error 通常表示严重错误，比如内存溢出，程序一般无法处理；Exception 表示程序可以处理的异常，又分为受检异常和运行时异常。

## 29. Error 和 Exception 有什么区别？

区别：

- Error：严重错误，通常无法恢复
- Exception：程序异常，可以捕获并处理

面试回答：

Error 通常表示 JVM 或系统级严重问题，比如 OutOfMemoryError、StackOverflowError，应用程序一般不主动捕获。Exception 表示程序运行中可以处理的问题，比如参数错误、空指针、文件不存在等，通常可以通过代码进行处理或向上抛出。

## 30. 受检异常和非受检异常有什么区别？

受检异常：

- 编译期强制处理
- 要么 try-catch
- 要么 throws

非受检异常：

- 编译期不强制处理
- 通常是 RuntimeException 或其子类

面试回答：

受检异常在编译期必须处理，否则无法通过编译，比如 IOException。非受检异常通常是 RuntimeException 及其子类，编译器不强制处理，比如 NullPointerException、IllegalArgumentException。运行时异常大多表示程序逻辑问题。

## 31. throw 和 throws 有什么区别？

`throw`：

- 用在方法体中
- 主动抛出一个异常对象

`throws`：

- 用在方法声明上
- 声明方法可能抛出的异常类型

面试回答：

throw 是实际抛出异常，后面跟具体异常对象；throws 是方法声明的一部分，用来告诉调用方这个方法可能抛出哪些异常。一个是动作，一个是声明。

## 32. finally 一定会执行吗？

大多数情况下会执行，但不是绝对。

不会执行的情况：

- JVM 退出，比如 `System.exit`
- JVM 崩溃
- 线程被强制终止

面试回答：

finally 通常会执行，即使 try 或 catch 中 return 了，也会先执行 finally。但不是绝对，比如调用 System.exit 直接退出 JVM，或者 JVM 崩溃，finally 就不会执行。

## 33. final、finally、finalize 有什么区别？

区别：

- final：关键字，表示不可变
- finally：异常处理中的代码块
- finalize：Object 的方法，曾用于对象回收前调用

面试回答：

final 是关键字，可以修饰类、方法和变量；finally 是异常处理语法中的代码块，通常用于释放资源；finalize 是 Object 的方法，过去用于对象被回收前执行清理逻辑，但不可靠，不推荐使用。

## 34. 什么是泛型？

泛型是参数化类型。

示例：

```java
class Result<T> {
    private T data;
}
```

面试回答：

泛型可以把类型作为参数传入类、接口或方法中，提高代码复用性和类型安全。使用泛型后，编译器可以在编译期做类型检查，减少强制类型转换。

## 35. Java 泛型为什么说是类型擦除？

原因：

Java 泛型主要在编译期生效，编译后泛型类型信息会被擦除。

面试回答：

Java 泛型是通过类型擦除实现的。泛型主要用于编译期类型检查，编译后泛型类型会被擦除成原始类型或上界类型，所以运行时通常拿不到完整的泛型类型信息。这也是为什么不能直接创建泛型数组、不能用基本类型作为泛型参数。

## 36. 什么是反射？

反射是在运行时获取类信息、创建对象、调用方法、访问字段的能力。

面试回答：

反射允许程序在运行时动态获取类的结构信息，比如类名、方法、字段、构造方法，也可以动态创建对象和调用方法。Spring、MyBatis、注解解析、测试框架等都大量使用了反射。

## 37. 反射有什么优缺点？

优点：

- 灵活
- 可以运行时动态操作类
- 支持框架通用能力

缺点：

- 性能相对普通调用低
- 破坏封装
- 编译期不容易发现错误
- 代码可读性相对差

面试回答：

反射的优点是灵活，可以在运行时动态操作类，因此很多框架都依赖反射实现通用能力。缺点是性能比直接调用低，也可能破坏封装，并且很多错误要到运行时才暴露。所以业务代码中不应该滥用反射。

## 38. 什么是注解？

注解是 Java 中给代码添加元数据的一种方式。

常见注解：

- `@Override`
- `@Deprecated`
- `@SuppressWarnings`
- `@Service`
- `@Autowired`
- `@Transactional`

面试回答：

注解本身不会直接改变程序逻辑，它更像是元数据标记。框架或工具可以通过反射读取注解，然后执行对应逻辑。比如 Spring 会扫描 `@Service` 创建 Bean，通过 `@Transactional` 生成事务代理。

## 39. 注解的生命周期有哪些？

由 `@Retention` 指定：

- SOURCE：只存在源码中
- CLASS：编译到 class 文件中，运行时不可读取
- RUNTIME：运行时仍然存在，可以通过反射读取

面试回答：

注解的生命周期由 RetentionPolicy 控制。SOURCE 只在源码阶段存在，CLASS 会进入字节码但运行时不可反射读取，RUNTIME 运行时仍然保留，可以通过反射获取。Spring 中很多注解都是 RUNTIME 级别。

## 40. 内部类有哪些类型？

常见内部类：

- 成员内部类
- 静态内部类
- 局部内部类
- 匿名内部类

面试回答：

Java 内部类可以定义在类内部、方法内部，也可以是匿名形式。成员内部类依赖外部类对象，静态内部类不依赖外部类对象。匿名内部类通常用于临时实现接口或继承类，但现在很多场景可以用 Lambda 简化。

## 41. 访问修饰符有哪些？

访问范围：

```text
private      当前类
default      同包
protected    同包 + 子类
public       任意位置
```

面试回答：

Java 有四种访问控制级别：private 只能在当前类访问；不写修饰符表示默认访问权限，只能在同包访问；protected 可以在同包和不同包子类中访问；public 可以在任何地方访问。

## 42. 构造方法有什么特点？

特点：

- 方法名和类名相同
- 没有返回值
- 创建对象时调用
- 可以重载

面试回答：

构造方法用于对象初始化，创建对象时会被调用。它的方法名必须和类名相同，没有返回值。一个类可以有多个构造方法形成重载。如果没有显式定义构造方法，编译器会提供一个无参构造方法；如果定义了构造方法，默认无参构造就不会自动生成。

## 43. Java 是值传递还是引用传递？

Java 只有值传递。

面试回答：

Java 中方法参数传递都是值传递。基本类型传递的是值的副本；引用类型传递的是引用地址的副本。方法内部可以通过这个地址副本修改对象内容，但不能改变外部引用本身指向的对象。

示例：

```java
void change(User user) {
    user = new User();
}
```

这里不会改变外部变量的指向。

## 44. 为什么 Java 不支持多继承？

原因：

- 避免多个父类中相同方法导致调用歧义
- 降低继承体系复杂度

面试回答：

Java 不支持类的多继承，主要是为了避免多继承带来的复杂性和方法冲突问题。比如两个父类都有同名方法，子类继承后调用时会产生歧义。Java 通过接口多实现来弥补单继承的不足。

## 45. 什么是不可变对象？

不可变对象是创建后状态不能改变的对象。

典型例子：

- String
- Integer
- Long
- LocalDate

面试回答：

不可变对象一旦创建，内部状态就不能再改变。它的优点是线程安全、可以安全共享、适合缓存，也适合作为 key。设计不可变类时，通常类用 final 修饰，字段用 private final 修饰，不提供修改方法，对可变引用要做防御性拷贝。

## 46. 如何创建一个不可变类？

常见做法：

- 类用 `final` 修饰
- 字段用 `private final`
- 构造方法完成初始化
- 不提供 setter
- 对可变对象做防御性拷贝

面试回答：

创建不可变类时，要保证对象创建后状态不能改变。通常会把类声明为 final，防止子类破坏不可变性；字段声明为 private final；不提供 setter；如果字段是可变对象，构造和 getter 中都要进行防御性拷贝。

## 47. Java 中创建对象有哪些方式？

常见方式：

- 使用 `new`
- 反射
- clone
- 反序列化
- 工厂方法

面试回答：

最常见的对象创建方式是 new。除此之外，还可以通过反射调用构造方法创建对象，通过 clone 复制对象，通过反序列化恢复对象，或者通过工厂方法封装对象创建逻辑。

## 48. 什么是枚举？

枚举用于定义一组固定常量。

示例：

```java
enum Status {
    SUCCESS, FAIL
}
```

面试回答：

枚举适合表示固定范围的取值，比如订单状态、性别、任务状态等。相比普通常量，枚举类型更安全，可读性更好，也可以定义字段、构造方法和普通方法。

## 49. 为什么枚举适合实现单例？

原因：

- 写法简单
- 天然防止反射破坏
- 天然支持序列化机制

面试回答：

枚举实现单例是 Effective Java 推荐的方式。它写法简单，并且 JVM 保证枚举实例的唯一性。相比普通单例，枚举单例能更好地防止反射和反序列化破坏单例。

## 51.【高频】为什么说 Java 是编译与解释并存？

核心：

- Java 源码先通过 `javac` 编译成字节码
- JVM 可以解释执行字节码
- JVM 也可以通过 JIT 把热点代码编译成本地机器码

面试回答：

Java 不是单纯的编译型语言，也不是单纯的解释型语言。Java 源码会先被 javac 编译成字节码，这是编译过程；字节码运行时由 JVM 解释执行，同时热点代码会被 JIT 编译成本地机器码，提高执行效率。所以说 Java 是编译与解释并存。

## 52.【高频】什么是字节码？使用字节码有什么好处？

字节码是 `.class` 文件中的平台无关指令。

好处：

- 实现跨平台
- JVM 可以做统一优化
- 兼顾解释执行和 JIT 编译

面试回答：

字节码是 Java 源码编译后的中间形式，不直接依赖具体操作系统和 CPU。不同平台上的 JVM 都能识别同一份字节码，因此 Java 可以跨平台。同时 JVM 可以在运行时对字节码进行解释执行、JIT 编译和运行期优化。

## 53. Java SE 和 Java EE 有什么区别？

区别：

- Java SE：标准版，包含 Java 基础语法、集合、IO、并发、JVM 等基础能力
- Java EE：企业版，面向企业级开发，包含 Servlet、JSP、JPA 等规范

面试回答：

Java SE 是 Java 的标准基础平台，提供语言基础和核心类库。Java EE 是在 Java SE 基础上的企业级规范集合，用于开发 Web 应用和企业级系统。现在很多 Java EE 规范迁移到了 Jakarta EE，日常开发中更多通过 Spring 生态使用这些能力。

## 54. Oracle JDK 和 OpenJDK 有什么区别？

核心：

- OpenJDK 是开源实现
- Oracle JDK 基于 OpenJDK 构建，并可能包含商业支持和部分工具差异
- 现代版本二者差异已经明显变小

面试回答：

OpenJDK 是 Java 平台的开源实现，Oracle JDK 基于 OpenJDK 构建。早期二者在部分工具、授权和商业特性上有区别，现代版本核心功能差异已经很小。企业选型时更需要关注版本、授权、长期支持和安全更新。

## 55. Java 和 C++ 有什么区别？

常见区别：

- Java 运行在 JVM 上，C++ 通常直接编译成本地机器码
- Java 不支持指针直接操作，C++ 支持指针
- Java 有自动垃圾回收，C++ 通常需要手动管理内存
- Java 只支持类单继承，C++ 支持多继承

面试回答：

Java 更强调跨平台、安全性和自动内存管理，程序运行在 JVM 上；C++ 更接近底层，性能和内存控制能力更强，但开发复杂度也更高。Java 没有指针直接操作，内存由 GC 管理，而 C++ 需要开发者更关注内存释放和对象生命周期。

## 56.【高频】String 的 intern 方法有什么作用？

作用：

- 尝试把字符串放入字符串常量池
- 返回字符串常量池中对应字符串对象的引用

面试回答：

`intern` 方法用于获取字符串在常量池中的引用。如果常量池中已经存在内容相同的字符串，就返回常量池中的引用；如果不存在，就把当前字符串内容加入常量池并返回对应引用。它常用于理解字符串常量池和 `==` 比较问题，实际业务代码中不建议滥用。

## 57.【高频】字符串拼接用 `+` 还是 StringBuilder？

核心：

- 少量、简单拼接可以用 `+`
- 循环中大量拼接建议用 StringBuilder
- 编译器可能会把简单 `+` 优化成 StringBuilder

面试回答：

如果是少量字符串拼接，直接用 `+` 可读性更好，编译器也会做优化。但如果在循环中频繁拼接字符串，建议显式使用 StringBuilder，避免产生大量临时对象，性能更稳定。

## 58. String 类型变量和常量做 `+` 运算时有什么区别？

核心：

- 字面量常量拼接可能在编译期优化
- 变量参与拼接通常在运行期完成

面试回答：

如果 `+` 两边都是字符串字面量或编译期常量，编译器可能直接把它们优化成一个常量字符串。如果有变量参与，通常需要在运行期通过 StringBuilder 等方式完成拼接。因此看 `==` 结果时，要区分编译期常量拼接和运行期变量拼接。

## 59.【高频】JDK 动态代理和 CGLIB 动态代理有什么区别？

区别：

- JDK 动态代理基于接口
- CGLIB 动态代理基于继承生成子类
- JDK 动态代理要求目标类实现接口
- CGLIB 不能代理 final 类和 final 方法

面试回答：

JDK 动态代理通过实现目标接口生成代理对象，因此目标类必须有接口。CGLIB 通过继承目标类生成子类代理，不要求目标类实现接口，但不能代理 final 类和 final 方法。Spring AOP 中，如果目标类有接口通常可以使用 JDK 动态代理，没有接口时可以使用 CGLIB。

## 60. 静态代理和动态代理有什么区别？

区别：

- 静态代理：代理类在编译期就写好
- 动态代理：运行时动态生成代理对象

面试回答：

静态代理需要手写代理类，每个被代理类可能都要对应一个代理类，代码量较大。动态代理是在运行时生成代理对象，可以对一类对象进行统一增强，更适合框架实现，比如 Spring AOP 的事务、日志、权限等功能。

## 61. 什么是 SPI？

SPI 是 Service Provider Interface，服务提供者接口。

面试回答：

SPI 是一种扩展机制，接口由调用方定义，具体实现由外部提供，并通过配置文件让程序在运行时加载实现类。它常用于框架扩展，比如 JDBC 驱动加载、日志门面实现加载等。SPI 更偏向“插件式扩展”，API 更偏向“调用已有能力”。

## 62. SPI 和 API 有什么区别？

区别：

- API：调用方使用服务提供方提供的能力
- SPI：框架定义规范，由外部实现方提供实现

面试回答：

API 是应用调用别人提供的接口，调用方向外部能力发起调用。SPI 则是框架定义扩展点，由第三方提供实现，框架在运行时加载这些实现。简单说，API 是我调用别人，SPI 是别人扩展我。

## 63.【高频】什么是序列化和反序列化？

定义：

- 序列化：把对象转换成可存储或传输的形式
- 反序列化：把存储或传输的数据还原成对象

面试回答：

序列化是把 Java 对象转换成字节流、JSON、二进制等形式，方便网络传输或持久化存储。反序列化则是把这些数据重新恢复成对象。RPC、缓存、消息队列、对象持久化等场景都会涉及序列化。

## 64. transient 关键字有什么作用？

作用：

- 修饰字段
- 表示该字段不参与 JDK 默认序列化

面试回答：

`transient` 用于修饰成员变量，表示该字段在 JDK 默认序列化时会被忽略。它适合修饰敏感信息、临时状态、可重新计算的数据等。不过它只影响 Java 原生序列化，对 JSON 框架不一定生效。

## 65.【高频】为什么不推荐使用 JDK 自带序列化？

原因：

- 性能相对较差
- 序列化后体积较大
- 存在安全风险
- 跨语言支持不好

面试回答：

JDK 自带序列化使用方便，但性能和序列化体积都不理想，也存在反序列化安全风险，跨语言能力也比较弱。因此实际项目里更常用 JSON、Protobuf、Kryo、Hessian 等序列化方案，具体选择要看可读性、性能和跨语言需求。

## 66.【高频】BigDecimal 为什么不能用 double 构造？

原因：

- double 本身可能已经存在二进制精度误差
- `new BigDecimal(double)` 会把误差带进去

面试回答：

BigDecimal 常用于金额等高精度计算，但不建议使用 double 构造，因为 double 在二进制表示中可能已经存在精度误差，BigDecimal 会把这个误差保留下来。推荐使用字符串构造，或者使用 `BigDecimal.valueOf`。

## 67. BigDecimal 比较大小为什么推荐 compareTo？

区别：

- `equals` 会比较数值和精度
- `compareTo` 只比较数学意义上的大小

面试回答：

BigDecimal 的 equals 不仅比较数值，还会比较 scale，比如 `1.0` 和 `1.00` 用 equals 可能不相等。compareTo 更符合数值比较语义，只比较大小，所以金额大小判断通常使用 compareTo。

## 68. 什么是 try-with-resources？

作用：

- 自动关闭实现了 `AutoCloseable` 的资源
- 避免手写 finally 关闭资源

面试回答：

try-with-resources 是 Java 7 引入的语法，用于自动关闭资源。只要资源实现了 AutoCloseable 接口，就可以放在 try 后面的括号中，代码执行结束后会自动关闭资源。它比手写 finally 更简洁，也更不容易遗漏关闭逻辑。

## 69. Throwable 常用方法有哪些？

常用方法：

- `getMessage`
- `getCause`
- `printStackTrace`
- `getStackTrace`

面试回答：

Throwable 是异常体系的顶层类，常用方法包括 getMessage 获取异常信息，getCause 获取原因异常，printStackTrace 打印堆栈，getStackTrace 获取堆栈数组。实际项目中一般通过日志框架记录异常堆栈。

## 70. Java 中常见语法糖有哪些？

常见语法糖：

- 自动装箱和拆箱
- 泛型
- 增强 for 循环
- switch 支持 String 和枚举
- Lambda 表达式
- try-with-resources
- 可变长参数

面试回答：

语法糖是编译器提供的简化写法，不改变底层能力。Java 中常见语法糖有自动装箱拆箱、泛型、增强 for、Lambda、try-with-resources、可变长参数等。编译后它们会被转换成 JVM 能理解的普通字节码结构。

示例：

回答 String 为什么不可变：

```text
String 是不可变对象，创建后内容不能修改。
这样可以保证线程安全，也方便字符串常量池复用。
同时 String 经常作为 key，不可变能保证 hashCode 稳定。
需要频繁拼接字符串时，不建议直接使用 String，可以使用 StringBuilder。
```
