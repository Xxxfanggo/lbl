## 基础概念与常识

### 1. Java 语言有哪些特点？

1. 简单易学（语法简单，上手容易）
2. 面向对象（封装，继承，多态）
3. 平台无关性（Java 虚拟机实现平台无关性）
4. 支持多线程
5. 可靠性（具备异常处理和自动内存管理机制）
6. 安全性（Java 语言本身的设计就提供了多重安全防护机制）
7. 高效性（通过 Just In Time 编译器等技术的优化）
8. 支持网络编程并且很方便
9. 编译与解释并存

---

### 2. Java SE 和 Java EE 有什么区别？

- **Java SE（Java Platform, Standard Edition）**：Java 平台标准版，Java 编程语言的基础，包含核心类库和虚拟机等核心组件。用于构建桌面应用程序或简单的服务器应用程序。
- **Java EE（Java Platform, Enterprise Edition）**：Java 平台企业版，建立在 Java SE 的基础上，包含了支持企业级应用程序开发和部署的标准和规范（如 Servlet、JSP、EJB、JDBC、JPA 等）。用于构建分布式、可移植、健壮、可伸缩和安全的服务端 Java 应用程序。

---

### 3. JVM、JDK、JRE 有什么区别？

- **JVM（Java Virtual Machine）**：Java 虚拟机，运行 Java 字节码的虚拟机。不同系统有特定实现，目的是使用相同的字节码在不同平台上运行。
- **JDK（Java Development Kit）**：功能齐全的 Java 开发工具包，包含 JRE、编译器 javac 和其他工具（javadoc、jdb、javap 等）。
- **JRE（Java Runtime Environment）**：运行已编译 Java 程序所需的环境，包含 JVM 和 Java 基础类库。

简单来说：JRE 只包含运行 Java 程序所需的环境，JDK 包含开发和调试工具。

---

### 4. 什么是字节码？采用字节码有什么好处？

在 Java 中，JVM 可以理解的代码就叫做字节码（即扩展名为 `.class` 的文件），它不面向任何特定的处理器，只面向虚拟机。

**好处**：
- Java 语言通过字节码的方式，在一定程度上解决了传统解释型语言执行效率低的问题
- 同时保留了解释型语言可移植的特点
- Java 程序无须重新编译便可在多种不同操作系统的计算机上运行

**编译与解释并存**：
- Java 程序要经过先编译（生成字节码），后解释（由 JVM 解释执行）两个步骤
- JIT（Just in Time Compilation）编译器在运行时将热点代码编译成机器码，下次可直接使用

---

### 5. 为什么说 Java 语言"编译与解释并存"？

Java 语言既具有编译型语言的特征，也具有解释型语言的特征：
- **编译型语言**：通过编译器将源代码一次性翻译成可被该平台执行的机器码（C、C++、Go、Rust）
- **解释型语言**：通过解释器一句一句地将代码解释为机器代码后再执行（Python、JavaScript、PHP）

Java 程序要经过先编译，后解释两个步骤：由 Java 编写的程序需要先经过编译步骤，生成字节码（`.class` 文件），这种字节码必须由 Java 解释器来解释执行。

---

### 6. AOT 有什么优点？为什么不全部使用 AOT 呢？

**AOT（Ahead of Time Compilation）** 是 JDK 9 引入的编译模式，在程序被执行前就将其编译成机器码，属于静态编译。

**AOT 的优点**：
- 提高启动速度，避免预热时间长
- 减少内存占用
- 增强 Java 程序的安全性（AOT 编译后的代码不容易被反编译和修改）
- 适合云原生场景

**JIT 与 AOT 对比**：

| 对比维度 | JIT（即时编译） | AOT（提前编译） |
|----------|------------------|-----------------|
| 编译时机 | 运行时编译 | 运行前编译 |
| 启动速度 | 较慢（需要预热） | 快（无需预热） |
| 峰值性能 | 更高（运行时优化） | 较低 |
| 内存占用 | 较高 | 较低 |
| 动态特性支持 | 完全支持 | 受限 |

**不全部使用 AOT 的原因**：
- AOT 编译无法支持 Java 的一些动态特性，如反射、动态代理、动态加载、JNI 等
- 很多框架和库（如 Spring、CGLIB）都用到了这些特性

### 7. Oracle JDK 和 OpenJDK 有什么区别？如何选择？

**主要区别**：

| 区别 | Oracle JDK | OpenJDK |
|------|------------|---------|
| 是否开源 | 不完全开源 | 完全开源 |
| 是否免费 | 部分版本免费（有时间限制） | 完全免费 |

**如何选择**：建议选择 OpenJDK 或基于 OpenJDK 的发行版，如 AWS 的 Amazon Corretto、阿里巴巴的 Alibaba Dragonwell。

### 8. Java 和 C++ 的区别？

- Java 不提供指针来直接访问内存，程序内存更加安全
- Java 的类是单继承的，C++ 支持多重继承；虽然 Java 的类不可以多继承，但接口可以多继承
- Java 有自动内存管理垃圾回收机制（GC），不需要程序员手动释放无用内存
- C++ 同时支持方法重载和操作符重载，但 Java 只支持方法重载
- ……

## 基本语法

### 9. 注释有哪几种形式？

Java 中的注释有三种：
1. **单行注释**：`//` 注释内容，用于解释方法内某单行代码的作用
2. **多行注释**：`/* 注释内容 */`，用于解释一段代码的作用
3. **文档注释**：`/** 注释内容 */`，用于生成 Java 开发文档

---

### 10. 标识符和关键字的区别是什么？

- **标识符**：就是名字，用于给程序、类、变量、方法等取名字
- **关键字**：是被 Java 语言赋予特殊含义的标识符，只能用于特定的地方

---

### 11. Java 语言关键字有哪些？

| 分类 | 关键字 |
|------|--------|
| 访问控制 | private、protected、public |
| 类，方法和变量修饰符 | abstract、class、extends、final、implements、interface、native、new、static、strictfp、synchronized、transient、volatile、enum |
| 程序控制 | break、continue、return、do、while、if、else、for、instanceof、switch、case、default、assert |
| 错误处理 | try、catch、throw、throws、finally |
| 包相关 | import、package |
| 基本类型 | boolean、byte、char、double、float、int、long、short |
| 变量引用 | super、this、void |
| 保留字 | goto、const |

### 12. 自增自减运算符有什么区别？

`++` 和 `--` 运算符可以放在变量之前，也可以放在变量之后：

- **前缀形式**（`++a` 或 `--a`）：先自增/自减变量的值，然后再使用该变量
- **后缀形式**（`a++` 或 `a--`）：先使用变量的当前值，然后再自增/自减变量

**记忆口诀**：符号在前就先加/减，符号在后就后加/减。

**示例**：
```java
int a = 9;
int b = a++;  // b=9, a=10
int c = ++a;  // c=11, a=11
```

---

### 13. 移位运算符有哪几种？有什么区别？

Java 中有三种移位运算符：

| 运算符 | 名称 | 规则 | 效果 |
|--------|------|------|------|
| `<<` | 左移 | 高位丢弃，低位补零 | 相当于 × 2^n |
| `>>` | 带符号右移 | 高位补符号位，低位丢弃 | 相当于 ÷ 2^n |
| `>>>` | 无符号右移 | 高位补 0，低位丢弃 | 逻辑右移 |

**注意**：
- `double` 和 `float` 不能进行移位操作
- 移位操作符只支持 `int` 和 `long` 类型
- 如果移位的位数超过数值所占有的位数，会先求余后再进行移位

---

### 14. continue、break 和 return 的区别是什么？

- `continue`：跳出当前的这一次循环，继续下一次循环
- `break`：跳出整个循环体，继续执行循环下面的语句
- `return`：跳出所在方法，结束该方法的运行

## 基本数据类型

### 15. Java 中的几种基本数据类型了解么？

Java 中有 8 种基本数据类型：

- **6 种数字类型**：
  - 4 种整数型：`byte`、`short`、`int`、`long`
  - 2 种浮点型：`float`、`double`
- **1 种字符类型**：`char`
- **1 种布尔型**：`boolean`

| 基本类型 | 位数 | 字节 | 默认值 | 取值范围 |
|----------|------|------|--------|----------|
| `byte` | 8 | 1 | 0 | -128 ~ 127 |
| `short` | 16 | 2 | 0 | -32768 ~ 32767 |
| `int` | 32 | 4 | 0 | -2147483648 ~ 2147483647 |
| `long` | 64 | 8 | 0L | -9223372036854775808 ~ 9223372036854775807 |
| `char` | 16 | 2 | 'u0000' | 0 ~ 65535 |
| `float` | 32 | 4 | 0f | 1.4E-45 ~ 3.4028235E38 |
| `double` | 64 | 8 | 0d | 4.9E-324 ~ 1.7976931348623157E308 |
| `boolean` | 1 | - | false | true、false |

---

### 16. 基本类型和包装类型有什么区别？

- **用途**：包装类型可用于泛型，而基本数据类型不可以
- **存储方式**：基本数据类型的局部变量存放在栈中，成员变量存放在堆中；包装类型属于对象类型，存在堆中
- **占用空间**：基本数据类型占用的空间往往非常小
- **默认值**：成员变量包装类型不赋值就是 `null`，基本类型有默认值
- **比较方式**：基本数据类型用 `==` 比较值，包装类型用 `equals()` 比较内容

---

### 17. 包装类型的缓存机制了解么？

Java 基本数据类型的包装类型大部分都用到了缓存机制来提升性能：

- `Byte`、`Short`、`Integer`、`Long`：默认创建了数值 **[-128，127]** 的缓存
- `Character`：创建了数值 **[0,127]** 的缓存
- `Boolean`：直接返回 `TRUE` 或 `FALSE`

对于 `Integer`，可以通过 JVM 参数 `-XX:AutoBoxCacheMax=<size>` 修改缓存上限。

```java
Integer i1 = 40;  // 使用缓存
Integer i2 = 40;  // 使用缓存
System.out.println(i1 == i2);  // true

Integer i3 = new Integer(40);  // 创建新对象
System.out.println(i1 == i3);  // false
```

**记住**：所有整型包装类对象之间值的比较，全部使用 `equals` 方法比较。

---

### 18. 自动装箱与拆箱了解吗？原理是什么？

- **装箱（Boxing）**：将基本类型用它们对应的引用类型包装起来
- **拆箱（Unboxing）**：将包装类型转换为基本数据类型

**原理**：
- 装箱调用 `valueOf()` 方法
- 拆箱调用 `xxxValue()` 方法

```java
Integer i = 10;  // 装箱，等价于 Integer.valueOf(10)
int n = i;       // 拆箱，等价于 i.intValue()
```

**注意**：频繁拆装箱会影响系统性能，应尽量避免不必要的拆装箱操作。

---

### 19. 为什么浮点数运算会有精度丢失的风险？

因为计算机是二进制的，且在表示一个数字时宽度有限。无限循环的小数存储在计算机时，只能被截断，导致小数精度发生损失。

```java
float a = 2.0f - 1.9f;
float b = 1.8f - 1.7f;
System.out.println(a == b);  // false
```

---

### 20. 如何解决浮点数运算的精度丢失问题？

使用 `BigDecimal` 可以实现对浮点数的精确运算，不会造成精度丢失。

```java
BigDecimal a = new BigDecimal("1.0");
BigDecimal b = new BigDecimal("1.00");
BigDecimal c = new BigDecimal("0.8");
BigDecimal x = a.subtract(c);  // 0.2
System.out.println(0 == x.compareTo(new BigDecimal("0.2")));  // true
```

---

### 21. 超过 long 整型的数据应该如何表示？

使用 `BigInteger` 内部使用 `int[]` 数组来存储任意大小的整型数据。

```java
BigInteger bigInteger = new BigInteger("9223372036854775808");
```

## 变量

### 22. 成员变量与局部变量的区别？

| 区别 | 成员变量 | 局部变量 |
|------|----------|----------|
| 语法形式 | 属于类，可被访问控制修饰符、static 等修饰 | 在代码块或方法中定义，不能被访问控制修饰符及 static 修饰 |
| 存储方式 | 使用 static 修饰属于类，不修饰属于实例，存在堆中 | 存在于栈内存 |
| 生存时间 | 随对象创建而存在，随对象销毁而消失 | 随方法调用而生成，随方法结束而消亡 |
| 默认值 | 有默认值（安全兜底机制） | 没有默认值，必须显式赋值 |

---

### 23. 静态变量有什么作用？

静态变量被 `static` 关键字修饰，可以被类的所有实例共享，无论一个类创建了多少个对象，它们都共享同一份静态变量。静态变量只会被分配一次内存，可以节省内存。

通常情况下，静态变量会被 `final` 关键字修饰成为常量。

---

### 24. 字符型常量和字符串常量的区别？

| 区别 | 字符常量 | 字符串常量 |
|------|----------|------------|
| 形式 | 单引号引起的一个字符 | 双引号引起的 0 个或若干个字符 |
| 含义 | 相当于一个整型值（ASCII 值） | 代表一个地址值（内存中存放位置） |
| 占内存大小 | 2 个字节 | 若干个字节 |

## 方法

### 25. 什么是方法的返回值？方法有哪几种类型？

方法的返回值是指方法执行后产生的结果。

**按返回值和参数分类**：
1. 无参数无返回值的方法
2. 有参数无返回值的方法
3. 有返回值无参数的方法
4. 有返回值有参数的方法

---

### 26. 静态方法为什么不能调用非静态成员？

1. 静态方法是属于类的，在类加载的时候就会分配内存，可以通过类名直接访问
2. 非静态成员属于实例对象，只有在对象实例化之后才存在
3. 在类的非静态成员不存在的时候静态方法就已经存在了，此时调用不存在的非静态成员是非法操作

---

### 27. 静态方法和实例方法有什么不同？

1. **调用方式**：
   - 静态方法可以使用 `类名.方法名` 或 `对象.方法名` 调用
   - 实例方法只能使用 `对象.方法名` 调用
   - 建议使用 `类名.方法名` 调用静态方法

2. **访问限制**：
   - 静态方法在访问本类成员时，只允许访问静态成员
   - 实例方法没有这个限制

---

### 28. 重载和重写有什么区别？

**重载（Overloading）**：
- 发生在同一个类中
- 方法名必须相同
- 参数类型、个数或顺序必须不同
- 方法返回值和访问修饰符可以不同
- 编译时绑定

**重写（Override）**：
- 发生在父类与子类之间
- 方法名、参数列表必须完全相同
- 返回值类型应比父类方法返回值类型更小或相等
- 抛出的异常范围小于等于父类
- 访问修饰符范围大于等于父类
- 运行时绑定

**总结**：
- 重载就是同一个类中多个同名方法根据不同的传参执行不同的逻辑
- 重写就是子类对父类方法的重新改造，外部样子不能改变，内部逻辑可以改变

**重写遵循"两同两小一大"**：
- 两同：方法名相同、形参列表相同
- 两小：返回值类型更小或相等，抛出异常更小或相等
- 一大：访问权限更大或相等

---

### 29. 什么是可变长参数？

从 Java 5 开始，允许定义可变长参数，即允许在调用方法时传入不定长度的参数。

```java
public static void method(String... args) {
    // args 是数组，可以传入 0 个或多个参数
}
```

**注意**：
- 可变参数只能作为函数的最后一个参数
- 遇到方法重载时，优先匹配固定参数的方法
- 编译后实际会被转换成一个数组

## 面向对象基础

### 30. 面向对象和面向过程的区别？

**面向过程编程（POP）**：把解决问题的过程拆成一个个方法，通过方法执行解决问题。

**面向对象编程（OOP）**：先抽象出对象，然后用对象执行方法的方式解决问题。

**OOP 的优点**：
- 易维护：由于良好的结构和封装性
- 易复用：通过继承和多态
- 易扩展：模块化设计

---

### 31. 创建一个对象用什么运算符？对象实例与对象引用有何不同？

- `new` 运算符创建对象实例
- 对象实例在堆内存中，对象引用指向对象实例（存放在栈内存中）
- 一个对象引用可以指向 0 个或 1 个对象
- 一个对象可以有 n 个引用指向它

---

### 32. 对象的相等和引用相等的区别？

- **对象的相等**：比较的是内存中存放的内容是否相等
- **引用相等**：比较的是指向的内存地址是否相等

---

### 33. 如果一个类没有声明构造方法，该程序能正确执行吗？

可以！因为即使没有声明构造方法，也会有默认的不带参数的构造方法。

如果自己添加了构造方法（无论是否有参），Java 就不会添加默认的无参构造方法了。

---

### 34. 构造方法有哪些特点？是否可被 override？

**特点**：
- 名称与类名相同
- 没有返回值，不能使用 `void` 声明
- 自动执行，无需显式调用

**能否被重写**：构造方法**不能被重写**，但**可以被重载**。

---

### 35. 面向对象三大特征是什么？

**封装**：把一个对象的状态信息隐藏在对象内部，不允许外部对象直接访问对象的内部信息，但可以提供一些可以被外界访问的方法来操作属性。

**继承**：使用已存在的类的定义作为基础建立新类的技术。新类的定义可以增加新的数据或新的功能，也可以用父类的功能。

**多态**：表示一个对象具有多种的状态，具体表现为父类的引用指向子类的实例。

---

### 36. 接口和抽象类有什么共同点和区别？

**共同点**：
- 都不能直接实例化
- 都可以包含抽象方法

**区别**：

| 区别 | 接口 | 抽象类 |
|------|------|--------|
| 设计目的 | 对类的行为进行约束 | 代码复用，强调所属关系 |
| 继承/实现 | 类可以实现多个接口 | 类只能继承一个类 |
| 成员变量 | 只能是 `public static final` | 可以有任何修饰符 |
| 方法（Java 8 前） | 只能是 `public abstract` | 可以包含抽象和非抽象方法 |
| 方法（Java 8+） | 可以有 `default`、`static`、`private` 方法 | 同上 |
| 内部类 | 不能有内部类 | 可以有内部类 |

---

### 37. 深拷贝和浅拷贝区别是什么？什么是引用拷贝？

- **浅拷贝**：会在堆上创建一个新对象，但如果原对象内部的属性是引用类型，浅拷贝会直接复制内部对象的引用地址
- **深拷贝**：完全复制整个对象，包括这个对象所包含的内部对象
- **引用拷贝**：两个不同的引用指向同一个对象

---

## Object

### 38. Object 类的常见方法有哪些？

Object 类主要提供了以下 11 个方法：

1. `getClass()` - 返回当前运行时对象的 Class 对象
2. `hashCode()` - 返回对象的哈希码
3. `equals(Object obj)` - 比较两个对象的内存地址是否相等
4. `clone()` - 创建并返回当前对象的一份拷贝
5. `toString()` - 返回类的名字实例的哈希码的 16 进制的字符串
6. `notify()` - 唤醒一个在此对象监视器上等待的线程
7. `notifyAll()` - 唤醒在此对象监视器上等待的所有线程
8. `wait(long timeout)` - 暂停线程的执行
9. `wait(long timeout, int nanos)` - 暂停线程的执行，带有额外时间
10. `wait()` - 一直等待，没有超时时间
11. `finalize()` - 实例被垃圾回收器回收的时候触发的操作

---

### 39. == 和 equals() 的区别？

- **`==`**：
  - 对于基本数据类型，比较的是值
  - 对于引用数据类型，比较的是对象的内存地址

- **`equals()`**：
  - 不能用于判断基本数据类型的变量，只能用来判断两个对象是否相等
  - 类没有重写 `equals()` 方法时，等价于通过 "==" 比较
  - 类重写了 `equals()` 方法时，比较的是对象的值

---

### 40. hashCode() 有什么用？

`hashCode()` 的作用是获取哈希码（`int` 整数），用于确定该对象在哈希表中的索引位置。散列表的特点是能根据"键"快速地检索出对应的"值"。

---

### 41. 为什么要有 hashCode？

以 HashSet 检查重复为例：
1. HashSet 会先调用对象的 `hashCode()` 方法得到哈希值
2. 通过内部散列函数决定这个元素应该放在哪个桶里
3. 如果桶中已经有其他元素，会进一步调用 `equals()` 检查是否真的相同

通过先利用 `hashCode()` 缩小范围，再在桶内调用 `equals()` 做精确判断，大大减少了 `equals()` 的调用次数，提高了查找和插入的执行效率。

---

### 42. 为什么重写 equals() 时必须重写 hashCode() 方法？

因为两个相等的对象的 `hashCode` 值必须是相等的。如果重写 `equals()` 时没有重写 `hashCode()` 方法，可能导致 `equals` 方法判断是相等的两个对象，`hashCode` 值却不相等，这会破坏 HashMap、HashSet 等基于哈希表的容器的行为。

**总结**：
- `equals` 方法判断两个对象是相等的，那这两个对象的 `hashCode` 值也要相等
- 两个对象有相同的 `hashCode` 值，他们也不一定是相等的（哈希碰撞）

---

## String

### 43. String、StringBuffer、StringBuilder 的区别？

| 区别 | String | StringBuilder | StringBuffer |
|------|--------|---------------|--------------|
| 可变性 | 不可变 | 可变 | 可变 |
| 线程安全 | 线程安全（不可变） | 线程不安全 | 线程安全（加了同步锁） |
| 性能 | 每次修改生成新对象 | 直接操作本身 | 加了同步锁，性能较低 |
| 使用场景 | 操作少量数据 | 单线程操作大量数据 | 多线程操作大量数据 |

---

### 44. String 为什么是不可变的？

`String` 类中使用 `final` 关键字修饰字符数组来保存字符串，且 String 类被 `final` 修饰防止被继承。

`String` 真正不可变的原因：
1. 保存字符串的数组被 `final` 修饰且为私有的，并且 String 类没有提供/暴露修改这个字符串的方法
2. String 类被 `final` 修饰导致其不能被继承，进而避免了子类破坏 String 不可变

> 注意：Java 9 之后，String 的底层实现从 `char[]` 改成了 `byte[]`，以节省内存空间。

---

### 45. 字符串拼接用"+" 还是 StringBuilder？

- **编译期可以确定值的字符串常量**拼接，JVM 会进行优化，直接存入字符串常量池
- **编译期无法确定值的字符串**拼接，编译器会创建 `StringBuilder` 进行拼接

**循环内拼接**：避免使用 "+"，因为编译器不会创建单个 `StringBuilder` 以复用，会导致创建过多的 `StringBuilder` 对象。

```java
// 避免 - 循环内创建多个 StringBuilder
for (int i = 0; i < 1000; i++) {
    s += arr[i];  // 每次循环都会创建新的 StringBuilder
}

// 推荐 - 直接使用 StringBuilder
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000; i++) {
    sb.append(arr[i]);
}
```

---

### 46. String#equals() 和 Object#equals() 有何区别？

- `String` 中的 `equals` 方法是被重写过的，比较的是 String 字符串的值是否相等
- `Object` 的 `equals` 方法是比较的对象的内存地址

---

### 47. 字符串常量池的作用了解吗？

**字符串常量池**是 JVM 为了提升性能和减少内存消耗针对字符串专门开辟的一块区域，主要目的是避免字符串的重复创建。

```java
String aa = "ab";  // 直接从常量池获取
String bb = "ab";  // 直接从常量池获取
System.out.println(aa == bb);  // true
```

---

### 48. String s1 = new String("abc"); 这句话创建了几个字符串对象？

会创建 **1 个或 2 个**字符串对象：
1. 如果字符串常量池中不存在 "abc"：创建 2 个（一个在常量池，一个在堆中）
2. 如果字符串常量池中已存在 "abc"：只创建 1 个（在堆中）

---

### 49. String#intern 方法有什么作用？

`String.intern()` 是一个 `native` 方法，用来处理字符串常量池中的字符串对象引用：
1. 如果字符串常量池中已经有一个与调用方法的字符串内容相同的对象，返回常量池中的对象引用
2. 如果没有，将当前字符串对象的引用添加到字符串常量池中，并返回该引用

---

### 50. String 类型的变量和常量做"+"运算时发生了什么？

**编译期可以确定值的字符串**（常量字符串），jvm 会将其存入字符串常量池：

```java
String str3 = "str" + "ing";  // 编译器优化为 "string"，存入常量池
String str4 = str1 + str2;     // 运行时通过 StringBuilder 实现
```

**final 修饰的 String 变量**会被编译器当做常量处理：

```java
final String str1 = "str";
final String str2 = "ing";
String c = str1 + str2;  // 编译器优化为常量 "string"
```

## 异常

### 51. Exception 和 Error 有什么区别？

- **Exception**：程序本身可以处理的异常，可以通过 `catch` 进行捕获。分为 Checked Exception（受检查异常）和 Unchecked Exception（不受检查异常）
- **Error**：程序无法处理的错误，如 `VirtualMachineError`、`OutOfMemoryError` 等，JVM 一般会选择线程终止

---

### 52. ClassNotFoundException 和 NoClassDefFoundError 的区别？

- `ClassNotFoundException` 是 Exception，发生在使用反射等动态加载时找不到类，是可预期的
- `NoClassDefFoundError` 是 Error，是编译时存在的类在运行时链接不到了（如 jar 包缺失），是环境问题

---

### 53. Checked Exception 和 Unchecked Exception 有什么区别？

- **Checked Exception（受检查异常）**：Java 代码在编译过程中，如果未被 `catch` 或 `throws` 处理，编译无法通过。如 IO 相关的异常、`ClassNotFoundException`、`SQLException`
- **Unchecked Exception（不受检查异常）**：即使不处理也可以正常通过编译。如 `RuntimeException` 及其子类（`NullPointerException`、`IllegalArgumentException`、`ArrayIndexOutOfBoundsException` 等）

---

### 54. 你更倾向于使用 Checked Exception 还是 Unchecked Exception？

**默认使用 Unchecked Exception**。

可以把 Unchecked Exception（如 `NullPointerException`）看作是代码 Bug，对待 Bug 最好的方式是让它暴露出来去修复代码，而不是用 `try-catch` 掩盖它。

只在必要时使用 Checked Exception：当这个异常是业务逻辑的一部分，并且调用方必须处理它时（如余额不足异常）。

---

### 55. Throwable 类常用方法有哪些？

- `getMessage()` - 返回异常发生时的详细信息
- `toString()` - 返回异常发生时的简要描述
- `getLocalizedMessage()` - 返回异常对象的本地化信息
- `printStackTrace()` - 在控制台上打印 Throwable 对象封装的异常信息

---

### 56. try-catch-finally 如何使用？

- `try` 块：用于捕获异常
- `catch` 块：用于处理 try 捕获到的异常
- `finally` 块：无论是否捕获或处理异常，`finally` 块里的语句都会被执行

**注意**：
- 不要在 finally 语句块中使用 return！
- 当 try 语句和 finally 语句中都有 return 语句时，try 语句块中的 return 返回值会被忽略

---

### 57. finally 中的代码一定会执行吗？

**不一定**！在以下情况下不会执行：
1. finally 之前虚拟机被终止运行（如 `System.exit(1)`）
2. 程序所在的线程死亡
3. 关闭 CPU

---

### 58. 如何使用 try-with-resources 代替 try-catch-finally？

`try-with-resources` 是 Java 7 引入的语法，用于自动关闭资源：

```java
// 传统方式
try (Scanner scanner = new Scanner(new File("test.txt"))) {
    while (scanner.hasNext()) {
        System.out.println(scanner.nextLine());
    }
} catch (FileNotFoundException e) {
    e.printStackTrace();
}
```

**优点**：
- 代码更简短、更清晰
- 产生的异常对我们更有用
- 自动关闭资源

---

### 59. 异常使用有哪些需要注意的地方？

- 不要把异常定义为静态变量，每次手动抛出异常都需要手动 new 一个异常对象
- 抛出的异常信息一定要有意义
- 建议抛出更加具体的异常
- 避免重复记录日志

---

## 泛型

### 60. 什么是泛型？有什么作用？

**泛型（Generics）** 是 JDK 5 中引入的新特性。使用泛型参数可以增强代码的可读性以及稳定性。

**作用**：
- 编译器可以对泛型参数进行检测
- 通过泛型参数可以指定传入的对象类型
- 原生 `List` 返回类型是 Object，需要手动转换，泛型后编译器自动转换

---

### 61. 泛型的使用方式有哪几种？

**1. 泛型类**：
```java
public class Generic<T> {
    private T key;
    public T getKey() { return key; }
}
```

**2. 泛型接口**：
```java
public interface Generator<T> {
    T method();
}
```

**3. 泛型方法**：
```java
public static <E> void printArray(E[] inputArray) {
    for (E element : inputArray) {
        System.out.println(element);
    }
}
```

---

### 62. 项目中哪里用到了泛型？

- 自定义接口通用返回结果 `CommonResult<T>`
- 定义 `Excel` 处理类 `ExcelUtil<T>`
- 构建集合工具类（如 `Collections` 中的 `sort`、`binarySearch` 方法）

## 反射

### 63. 什么是反射？

Java 反射（Reflection）是一种**在程序运行时，动态地获取类的信息并操作类或对象（方法、属性）的能力**。

反射允许在**运行时**探知一个类有哪些方法、哪些属性、它的构造函数是怎样的，甚至可以动态地创建对象、调用方法或修改属性。

---

### 64. 反射有什么优缺点？

**优点**：
1. **灵活性和动态性**：可以动态加载类、创建对象、调用方法和访问字段
2. **框架开发的基础**：Spring、Hibernate、MyBatis 等框架大量使用反射实现依赖注入、AOP、ORM 等功能
3. **解耦合和通用性**：可以编写更通用、可重用和高度解耦的代码

**缺点**：
1. **性能开销**：反射操作比直接代码调用要慢
2. **安全性问题**：可以绕过 Java 语言的访问控制机制
3. **代码可读性和维护性**：过度使用反射使代码变得复杂、难以理解和调试

---

### 65. 反射的应用场景？

**1. 依赖注入与控制反转（IoC）**
Spring/Spring Boot 在启动时扫描带有特定注解的类，利用反射实例化对象并注入依赖。

**2. 注解处理**
框架通过反射检查类、方法、字段上的注解，然后根据注解信息执行相应逻辑。

**3. 动态代理与 AOP**
JDK 动态代理和 CGLIB 动态代理都离不开反射，`Method.invoke()` 用于调用真实对象的方法。

**4. 对象关系映射（ORM）**
MyBatis、Hibernate 通过反射获取 Java 类的属性列表，把查询结果对应到 Java 属性。

---

## 代理

### 66. 如何实现动态代理？

Java 中实现动态代理的两种主流方式：

**JDK 动态代理**：
- 要求目标类实现一个或多个接口
- 利用 `Proxy.newProxyInstance()` 动态创建代理类
- 调用被转发到 `InvocationHandler.invoke()` 方法

**CGLIB 动态代理**：
- 不要求被代理类实现接口
- 动态生成目标类的子类作为代理类
- 通过 ASM 字节码操作技术实现

---

### 67. 静态代理和动态代理有什么区别？

| 对比维度 | 静态代理 | 动态代理 |
|----------|----------|----------|
| 代理关系确定时机 | 编译期（生成固定的 .class 文件） | 运行时（动态生成代理类字节码） |
| 实现方式 | 手动编写代理类，一对一绑定 | 通过 Handler/Interceptor 封装增强逻辑 |
| 接口依赖 | 必须实现同一接口 | 支持代理接口或直接代理实现类 |
| 代码量 | 代码量大，维护成本高 | 代码量少，维护性好 |
| 典型应用 | 简单的装饰器模式 | Spring AOP、RPC 框架、ORM 框架 |

---

### 68. JDK 动态代理和 CGLIB 动态代理有什么区别？

1. JDK 动态代理要求被代理的类实现接口，原理是动态生成一个接口的实现类；CGLIB 不需要接口，原理是动态生成被代理类的子类
2. CGLIB 不能代理 `final` 的类，被代理的方法也不能是 `final` 或 `private`
3. 大部分情况下 JDK 动态代理效率更优秀，JDK 版本升级后优势更明显

---

### 69. 动态代理在框架中的实际应用场景？

动态代理最典型的应用场景是 **Spring AOP**。

AOP（面向切面编程）能够将那些与业务无关，却为业务模块所共同调用的逻辑或责任（如事务处理、日志管理、权限控制）封装起来，减少重复代码，降低模块间耦合度。

Spring AOP 基于动态代理：
- 如果被代理的对象实现了某个接口，使用 **JDK Proxy** 创建代理
- 如果没有实现接口，使用 **CGLIB** 生成被代理对象的子类作为代理

---

## 注解

### 70. 何谓注解？

`Annotation`（注解）是 Java5 开始引入的新特性，可以看作是一种特殊的注释，主要用于修饰类、方法或者变量，提供某些信息供程序在编译或者运行时使用。

注解本质是一个继承了 `Annotation` 的特殊接口：

```java
public @interface Override {
}
public interface Override extends Annotation {
}
```

---

### 71. 注解的解析方法有哪几种？

- **编译期直接扫描**：编译器在编译 Java 代码时扫描并处理，如 `@Override` 注解
- **运行期通过反射处理**：像 Spring 框架的 `@Value`、`@Component` 都是通过反射进行处理

---

## SPI

### 72. 何谓 SPI？

**SPI（Service Provider Interface）**：服务提供者的接口，专门提供给服务提供者或扩展框架功能开发者使用的接口。

SPI 将服务接口和具体的服务实现分离开来，将服务调用方和服务实现者解耦，能够提升程序的扩展性、可维护性。

很多框架都使用了 SPI 机制：Spring 框架、数据库加载驱动、日志接口、Dubbo 的扩展实现等。

---

### 73. SPI 和 API 有什么区别？

- **API**：实现方提供接口和实现，调用方通过接口调用实现方的功能。接口和实现都在实现方的包中。
- **SPI**：接口存在于调用方，由调用方确定接口规则，不同厂商根据规则实现。接口调用方和实现方解耦。

---

### 74. SPI 的优缺点？

**优点**：
- 大大提高接口设计的灵活性
- 提升程序的扩展性、可维护性
- 修改或替换服务实现不需要修改调用方

**缺点**：
- 需要遍历加载所有的实现类，不能做到按需加载，效率较低
- 当多个 `ServiceLoader` 同时 `load` 时，会有并发问题

---

## 序列化和反序列化

### 75. 什么是序列化？什么是反序列化？

- **序列化**：将数据结构或对象转换成可以存储或传输的形式（通常二进制字节流）
- **反序列化**：将在序列化过程中所生成的数据转换为原始数据结构或者对象的过程

**常见应用场景**：
- 对象在进行网络传输（RPC）之前需要序列化，接收时需要反序列化
- 将对象存储到文件之前需要序列化，从文件中读取需要反序列化
- 将对象存储到数据库（如 Redis）之前需要序列化，读取时需要反序列化

---

### 76. 如果有些字段不想进行序列化怎么办？

使用 `transient` 关键字修饰。

```java
private transient String password;
```

**注意**：
- `transient` 只能修饰变量，不能修饰类和方法
- `transient` 修饰的变量在反序列化后会被置成类型的默认值
- `static` 变量无论有没有 `transient` 关键字修饰都不会被序列化

---

### 77. 常见序列化协议有哪些？

- **JDK 自带**：一般不会用，效率低且存在安全问题
- **二进制序列化协议**：Hessian、Kryo、Protobuf、ProtoStuff
- **文本类序列化协议**：JSON、XML（可读性好，但性能较差）

---

### 78. 为什么不推荐使用 JDK 自带的序列化？

1. **不支持跨语言调用**：如果调用的是其他语言开发的服务就不支持了
2. **性能差**：序列化后的字节数组体积较大，传输成本加大
3. **存在安全问题**：当输入的反序列化数据可被用户控制时，可能产生非预期的对象，执行任意代码

---

## I/O

### 79. Java IO 流了解吗？

IO 即 `Input/Output`，输入和输出。数据输入到计算机内存的过程即输入，反之输出到外部存储的过程即输出。

Java IO 流的 40 多个类都是从以下 4 个抽象类派生的：
- `InputStream`/`Reader`：所有输入流的基类
- `OutputStream`/`Writer`：所有输出流的基类

---

### 80. I/O 流为什么要分为字节流和字符流呢？

1. 字符流是由 Java 虚拟机将字节转换得到的，这个过程比较耗时
2. 如果不知道编码类型，使用字节流的过程中很容易出现乱码问题

---

### 81. Java IO 中的设计模式有哪些？

主要涉及装饰器模式（Decorator Pattern）和适配器模式（Adapter Pattern）。

---

### 82. BIO、NIO 和 AIO 的区别？

- **BIO（Blocking I/O）**：同步阻塞 I/O，服务器实现模式为一个连接对应一个线程，适用于连接数目比较小且固定的场景。
- **NIO（New I/O / Non-blocking I/O）**：同步非阻塞 I/O，服务器实现模式为一个请求对应一个线程，适用于连接数目多且连接比较短（轻操作）的场景。
- **AIO（Asynchronous I/O）**：异步非阻塞 I/O，服务器实现模式为一个有效请求对应一个线程，适用于连接数目多且连接比较长（重操作）的场景。

## 语法糖

### 83. 什么是语法糖？

**语法糖（Syntactic sugar）**：编程语言为了方便程序员开发程序而设计的一种特殊语法，这种语法对编程语言的功能并没有影响，但实现相同的功能时，基于语法糖写出来的代码更简单简洁且更易阅读。

JVM 并不能识别语法糖，Java 语法糖需要先通过编译器进行解糖，才能被正确执行。

### 84. Java 中有哪些常见的语法糖？

Java 中最常用的语法糖主要有：
- 泛型
- 自动拆装箱
- 变长参数
- 枚举
- 内部类
- 增强 for 循环
- try-with-resources 语法
- lambda 表达式
- ……
